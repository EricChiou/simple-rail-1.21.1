| LC-P1（高優先級） | 中心持久票證持續累積，停車／刪車／關閉設定／重啟不回收 | `LocomotiveChunkLoader.forceCurrentChunk` 只有 add=true；`onUnload` 只清 queue。指定版 `ForcedChunkManager.reinstatePersistentChunks` 恢復持久集合。新增中心的數量隨行程增長，可能增加長期負載；沒有 TPS／記憶體量測，不填實測衰退數字。符合目前 D3，但不是適合最終交付的無上限生命週期。 |

## 已批准的 D3 修訂規格

1. **以整列目前需求維持集合，不累積歷史路線。** 以車頭 UUID＋維度為 owner，集合包含車頭與仍連結車廂的目前 chunk、下一次移動目標 chunk；每個必要中心加一圈 chunk 緩衝（3×3 聯集）。這是建議的新範圍，不是 OLD 等價移植，也不是整列只套車頭周圍 5×5。高速／斜坡／路口及長編組是否足夠由後續查證與人工驗收判定，不能只憑大小宣稱保證。
2. **差集更新。** 每輪先加入新增需求，確認可用後才釋放已不在集合的本 owner 票證。相同 owner／chunk 不重複申請；移除 25 次重複中心迴圈。票證數只與當前編組／缓衝有關，不隨行駛距離增加；不得在尾車尚需舊區塊時回收。未取得新 chunk 時應延後移動／回收，避免把列車切斷。
3. **停車保留，永久移除／停用釋放。** 停車維持當前整列必要集合，讓計時／重新發車可運作；車頭永久移除則釋放其全部票證；關閉設定立即釋放本 controller 全部票證（包括尚未實例化 owner），重新開啟時為已載入的列車重建。解除車廂連結後，從原 owner 的需求集合移出該車；不能移除其他列車持有的同一 chunk 票證。世界卸載／正常關服不等於永久刪車。
4. **持久保存当前有效集合與 owner 索引。** 正常重啟只恢復有效列車的目前集合，維持無玩家也能啟動；不能先恢復全歷史再逐一等玩家靠近清理。索引、NeoForge 保存、實體讀回的順序與一致性需專門查證／測試。`getEntity(UUID)==null` 不足以判定車頭／車廂永久不存在；暫時未載入不可誤刪。
5. **首次啟動邊界明確。** 新放置列車自動登錄；新版已登錄且設定啟用的列車，後續重啟應不需玩家靠近。從未登錄、又在未載入區域的實體仍需先載入一次；不增加全世界實體搜尋。
6. **R1 既有歷史票證的一次性處理（已批准）。** R1 沒有可靠的「目前 owner／所需集合」索引，不能從遍歷過的 chunk 集合猜出車頭位置。建議升級前備份 NEW 測試世界；首次使用新政策清理 `simplerail:locomotive` 的 R1 票證，既有列車各由玩家載入一次重建索引。只處理這個 controller，不刪實體、不影響原版或其他 controller 票證；不做 OLD 1.16.5 存檔轉換。若不接受一次性重新載入，須另定 R1 owner 發現／清理流程，不能聲稱可無損自動辨識。

載入／釋放的確切 API 呼叫時機、一次性處理的版本標記、保存 schema 與故障恢復細節均為**待查證**。目前 `TrainStops` 是跟車演算法的方格紀錄，不能未經核對就當作每一車廂最後實際持久位置；缺位置資料的處理必須在程式審查前定義，不用 `null` 推定車廂消失。
