## 1. T-002 舊版建置環境處理草案

本輪未執行 OLD build。已觀察到的就緒缺口是：宣告 Java 8，但在列明範圍只找到 Java 21／25；所查 Wrapper 快取未見 Gradle 6.8.1；ForgeGradle 4.1.+ 的實際解析版本未知。以下各項都是後續處理候選，不將尚未發生的網路／編譯失敗當作事實。

| 步驟／條件 | 建議處理 | 必須保存的證據與通過界線 |
| --- | --- | --- |
| 1. 尋找可用 Java 8 | 先核對是否有未列入本輪搜尋範圍的既有 JDK；若沒有，再選擇可追溯來源的 Java 8 JDK 供 OLD 使用。實際發行版／更新號及與舊 Wrapper 的搭配待查證 | JDK 來源、檔案雜湊、java／javac 版本與路徑；不把安裝成功當 build 成功 |
| 2. 隔離 OLD 執行環境 | 在明確的 OLD 工作副本及專用 Gradle user home 測試；僅於該執行程序指定 JAVA_HOME／必要 PATH，不改全域預設，不重設 OLD。副本應記錄來源 HEAD 與必要工作差異 | 執行目錄、來源指紋、程序環境、快取目錄及 Wrapper 版本結果；本輪未建立副本或修改環境 |
| 3. 取得原宣告 Wrapper distribution | 使用宣告的 Gradle 6.8.1-all，先做 --version，再進入已授權的 T-002 build。來源、下載能力、校驗與 JDK 搭配待查證 | 下載／版本命令、退出碼、log 與來源校驗依據；不能以 NEW 的 Gradle 9.2.1 代替 OLD 後宣稱原基線通過 |
| 4. 舊依賴下載／解析失敗時 | 保留第一個失敗的 artifact／repository 與完整錯誤，區分網路、權限、套件不存在與版本解析問題。先恢復相同基線所需的依賴；如需修改 repository／鎖定版本，另提具體變更及差異供審閱 | 實際選定 ForgeGradle 版本、依賴解析資料、重試前後命令與退出碼；不默默升級 Forge／Minecraft／Wrapper 或切換 mappings |
| 5. 真正建立 build 基線 | 環境就緒且 T-002 獲准後，再按其要求執行 Wrapper build | 必須退出碼 0、產出可識別 JAR、版本與雜湊一致，才可完成 T-002；只下載工具或嘗試 build 不能完成 |

若 OLD 最終無法重現建置，T-002 保留受阻原因；不得將查閱原始碼或外部既有 JAR 充當本專案 build 通過。NEW 的 T-005 分支不直接依賴 T-002，可在另獲執行授權後獨立推進；需要 OLD 執行期證據的調查與驗收仍維持其阻礙。

T-001 的沙箱內 NEW Wrapper 鎖檔失敗與沙箱外成功，顯示執行環境會影響快取路徑／存取；後續應記錄實際 user.home 與 Gradle user home，不能假設兩種執行方式相同。本輪不更改全域 Java home、使用者 Gradle 設定或專案檔案以掩蓋差異。

## 2. T-003 舊版遊戲基線受阻處理草案

1. 保留正式依賴 **T-003 → T-002**。只有已確認產物來源與版本後才建立隔離的 1.16.5 client／dedicated server 測試世界；不匯入 NEW。
2. 若 T-002 受阻，T-003 也不能標完成。可整理已知原始碼／靜態行為作輔助證據，但不得當作實際啟動、多人連線或六項疑點已重現。
3. 若之後取得可追溯的舊版發行 JAR，可另提「以該 JAR 暫作行為參考」的替代方案供使用者審閱；必須註明來源、版本、雜湊及與 OLD HEAD 的可比性。它不能倒推 T-002 build 已通過，也不能在未調整驗收規則前取代 T-003 原要求。
4. 若 client 因顯示、帳號或執行環境受阻，保留其錯誤；可提出先測 dedicated server 的分段方案，但 server 啟動不等於 client 連線／GUI／渲染已驗證。
5. 六項舊疑點逐一保存「已確認／未重現／證據不足」；環境不足屬證據不足，不能用「未重現」跳過後續修正判斷。待可測環境恢復，再補齊正式 T-003 與相關調查要求。
