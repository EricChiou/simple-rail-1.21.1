量測規格須在正式測試前定義：時鐘及單位、開始計時點、保存點、實際卸載／停止點、載入恢復點與放行點，以及容許誤差及其理由。保存到實際卸載之間若仍在運行，須按規格計入活動時間；不得只用保存時畫面的「3 秒」作唯一基準。計時停車讀回後實測等待應符合暫停前剩餘時間，卸載／離線間隔不能被扣除；公式與誤差的具體實作由 T-004／T-011 定義，本文件不預填毫秒門檻。

程式審查輸入／人工選用資料：帶時間戳的設定與計時資料、保存／卸載／停止／讀回／放行時間軸、區塊確實卸載的觀測、實測等待与差異計算、錄影及 log。完整整合版本須在 client 與 dedicated server 場景各跑卸載與離線路徑（T-083）；訊號另交 tick／紅石觀測時序。誤差或相位規格未定時，相關驗收受阻。

### C-04 專用方塊實體與 27 格不消耗樣板

依據：MIGRATION.md §3、§4.3(5)、D4；T-012、T-043–T-047、T-059–T-060、T-082。

- 確認發射器使用專用方塊實體及已定新增 ID，27 格索引為 0–26，箱子式 GUI 開關、槽位操作、兩端同步及名稱／內容存讀完整。
- 在沒有玩家另行編輯樣板的受控生成案例，逐格比較觸發前後 ItemStack：種類、數量、自訂名稱與相關資料均不變。玩家主動搬動槽位另按操作前後核對，避免把合法編輯誤判為生成消耗。
- 測空樣板、槽位空缺／間隔、不同原版車種、四水平朝向、扳手旋轉及阻擋位置；核對生成數量、種類、位置與順序。
- 整列案例包含第 0 格車頭、車頭在非第 0 格、多車頭、後續一般礦車及生成後運行。第 0 格的連結條件須正確；多車頭／空格／阻擋的精確行為依調查規格，不能自行決定玩法。
- 持续供電、重複鄰居更新、再次觸發須有 T-043 的來源參考／待確認差異及必要修正決策；不預設只能觸發一次，不自行加入節流或物品消耗。超出已定觸發規格的額外生成才判為問題；D4 的不消耗本身不是 bug。

程式審查輸入／人工選用資料：27 格完整前後快照、GUI 兩端狀態、玩家操作與紅石時序、生成實體 UUID／類型／座標、編組清單及容器保存重啟資料。只有畫面看見箱子或生成一輛車不足以通過。

### C-05 編組、恢復與整列移除

依據：MIGRATION.md §4.2、§4.3(1)；T-013、T-048、T-053–T-062、T-082、T-084。

- 核對車頭 UUID→有序車廂 UUID 的保存／重建責任；空列車、多節列車、正常跟車、停止位置、重複連結及破壞均有結果。
- 分別測跨區塊車廂、車頭先載入、車廂晚載入、暫時查不到 UUID、已移除與不合法引用。不能把查詢不到等同已刪除，直接丟棄仍有效的編組或次序。
- 檢查 static map／其他暫存的世界與維度範圍、同程序切換世界，以及 `prevPos`／`stopPos` 等暫存恢復；不預設具體重試或儲存機制。
- 扳手的相鄰格與四方向操作、無效點擊、已連結車廂及兩人操作只形成合法且不重複的連結；發射器整列次序與槽位規格一致。
- `destory_rail` 的一般車／整列移除、紅石條件、無關鄰車、乘客／容器車廂及掉落責任各自核對；不誤刪無關車，不留下編組索引或意外重複掉落。票證政策另依 C-07，不在刪車任務隱性變更。

程式審查輸入／人工選用資料：每步有序 UUID 清單（不能只比集合）、載入事件時間軸、維度／座標／軌跡、保存資料、實體與物品前後快照、server log 及雙 client 錄影。只測所有車廂同時載入不足以證明恢復正確。

### C-06 多人同步與執行端權責

依據：MIGRATION.md §3、§4.3(6)；T-007、T-089、T-014、T-049、T-052、T-058、T-063–T-065、T-084、T-086。

- T-007 只驗 server 啟停；T-089 建立單 client 連線基線，均不能代替下列多人功能驗收。
- 至少兩個 client 連同一 dedicated server，保留三端識別與相同受測版本；單人整合伺服器不能代替此項。
- 新玩家加入、重連、進出追蹤範圍、兩人同時操作均需測。比對車頭／車廂實體數、UUID、名称、8 朝向與 FACING／LINKABLE 對應欄位、編組次序、27 格槽位及方塊狀態。
- 覆核回呼在哪端執行、哪端修改狀態、哪端呈現效果；生成、刪除、連結、互動與計時不能因雙端執行產生額外副作用。不得僅由缺少 client/server 判斷語句斷言已有 bug，須查 API 與實測。
- 檢查 dedicated server 無 client-only 類別載入錯誤，模型／UV／9 軌道透明材質及 8 朝向實際顯示正確。
- T-084 補齊三種路口、票證、卸載、多列車、跨維度同座標及世界切換，不能以早期 T-065 已審代替整合回歸。

程式審查輸入／人工選用資料：三端原始 log、可對齊的操作／事件時間軸、雙端錄影及逐步狀態快照、初始同步與追蹤更新觀測。觀測時間點／允許同步等待依案例先定義；不以截取不同時刻的畫面推定永久不同步，也不能用「稍後正常」掩蓋重複實體。

### C-07 區塊載入與票證生命週期

依據：MIGRATION.md §4.2、§4.3(2)、D3／D6；T-016、T-075–T-080、T-083–T-084、T-087–T-088、T-126。

- OLD 參考須分開記錄「程式呼叫」與「實際結果（如有）」；未實測標「依原始碼推定／待確認」：radius 為 2，但迴圈反覆傳入中心座標；不能推定載入 25 個不同區塊，也不能把呼叫次數當票證數量。
- 核對 `disableLoadingChunk=true` 的實際啟用語意與預設；不能按名稱擅自反轉行為。目標 API 的 owner、維度、中心座標、載入及持續 tick 參數須有逐項對照；無法等價對應時列受阻。
- 在 NEW 新世界測進入／離開區塊、離開玩家範圍、停車、移除車頭、保存重啟、設定、跨維度及多列車；OLD 只在已有可用 JAR 且必要時選做針對觀察，不重建或要求其執行紀錄。觀察票證、实际載入集合、持續 tick 與列車活動；有票證不等同列車確實持續運作。
- T-077 先按 D3 原始碼呼叫與已查證 NEW API 對照規格判定，不宣稱 OLD 未測結果已等價驗證；T-078 區分 API 移植缺陷與原政策問題。範圍、釋放或上限改動須有具體前後規格、案例及使用者決策，才進入 T-079 對應變更；一般 TASK.md 審閱不能代替該政策決策。
- 沒有解除呼叫是待調查風險，不能在無實測時宣稱已發生洩漏。維持 D3 時，停車／刪車後自動釋放不列為通過條件；已確認而決定保留的限制須明列決策與實測後果，不能寫成已修復。
- T-080 依最終規格重跑並列出相對 D3 原碼邏輯規格的預期差異。同步核對 C-03 的真卸載前提；不得以被票證保留的區塊作計時卸載通過證據。

程式審查輸入／人工選用資料：OLD 原始碼呼叫與 NEW API／版本對照、NEW 設定副本、owner／維度／區塊座標集合、票證與實際載入／tick 時間軸、列車活動紀錄、重啟資料、負載量測原始值及必要政策審閱紀錄。OLD 實測附件只在確有觀察時提供；未取得的 log 或票證結果不補造。效能方法、場景、列車數、硬體及門檻先定義；門檻未決只可報觀測值，不能判效能通過。

## 5. 問題嚴重度與審查結論

嚴重度依實際影響判定，與是否容易修正無關。下列例子是假設分類，**不表示專案已確認有這些缺陷**。證據不足屬流程阻礙，不能自動推定為產品缺陷；可另記潛在影響，待調查確認。

| 等級 | 定義／例子 | 處理門檻 |
| --- | --- | --- |
| S0 致命 | 新世界損壞或無法讀回、廣泛且不可恢復的內容遺失、跨世界誤刪等 | 立即停止受影響案例及候選放行，保留現場；修正、程式複查及使用者重測前不得解除阻擋 |
| S1 重大 | 必要功能失效或違反 D1–D8：既有 ID 遺失／改名、編組丟失、樣板消耗、離線時間被扣除、多人重複實體、dedicated server 無法啟動、未授權改票證政策等 | 阻擋相關任務驗收及最終候選；須修正或取得具體需求決策後按新規格重驗，不能以一般風險接受覆蓋基線 |
| S2 一般 | 局部功能、狀態／設定／資源變體或邊界結果不符，影響可限定且無 S0／S1 後果 | 阻擋相關案例通過；必要完成條件仍不符時同樣阻擋最終完整驗收，不能因較低嚴重度跳過 |
| S3 輕微 | 不影響需求判定的說明、排版或證據索引可讀性問題，原始證據仍足以核對 | 可列待辦並記責任者及處置；若影響可追溯性或掩蓋未測項，改判受阻，必要時提高等級 |

嚴重度調整須由審查者記錄新證據與理由，保留原等級。沿用 D3 的已確認限制須與「移植未符合 D3」分開：前者可按 TASK.md 的政策保留流程處理，後者不能藉已知限制豁免。

| 審查狀態 | 可使用的情況 |
| --- | --- |
