# R1 案例、场景及事先預期

所有實際結果尚空白。R-03／R-F 先審程式與測例；使用者執行 SP（單人）與 DS（dedicated server＋連線 client），以下不由 Agent 操作。速度設定 0.4／0.8／2.0 是配置参数，不等於保證位移；本局部包只判斷方向／有效斜坡，完整速度量測與容差仍留 T-094／T-026。

## 共用坡底布局

以往東為例，z=100：

| 軌道位置 | 支撐位置 | 類型與預期 |
| --- | --- | --- |
| x=100–107，y=65 | 同 x，y=64 | 八格高速平軌，供電，shape=east_west |
| x=108，y=65 | x=108，y=64 | 第一格升坡，shape=ascending_east；類型依案例 |
| x=109–116，y=66 | 同 x，y=65 | 八格平軌供電，shape=east_west |

以紅石方塊作支撐可給動力軌持續供電；高側支撐是上坡必需的完整方塊。**坡底最後一格平軌與第一格升坡位於同 Y；第一格升坡與坡頂第一格平軌相差一格 Y。** 必須先放高側，再放升坡與低側，查看 shape；若舊軌道沒有更新，重新鋪接口，不改存檔資料。不要在旁邊多鋪支線；確保直線與完整支撐。西／南／北案例旋轉布局，依行進方向確認 ascending_west／south／north。

每次只放一部空原版 minecart，從坡前至少四格的供電高速直線進入，先有穩定正向動量；不要用玩家碰撞、拉回或抵牆起步來補結果。先做正向上坡，另從高側進入測下坡／坡頂。可使用原先回報的世界／路線作額外案例，但不要把不明 layout 與上述控制布局混為同例。

正常未供電制動、沒有足夠動量的上坡回滾或人工反向推車，均須與「連續供電直線進入有效坡底後意外反轉」區分。若全原版控制也反轉，記錄兩者結果；這是調查輸入，不能自動說高速已通過。無法確保供電／shape／動量時先標該例未判定，不能虛填通過。

## 案例

| ID | 操作／參數 | 預期與判定範圍 |
| --- | --- | --- |
| R1-001 | 高速作第一格斜坡，向東／西／南／北分别鋪。給電／斷電，查看 shape、外觀及圖案；SP／DS 各觀察 | 能成對應升坡；供電／未供電貼圖正確，無高速缺模型；不能據此簽全部模組資源無錯誤 |
| R1-002 | 在 NEW 備份世界，把原低處高速平軌接高一格軌道的接口重新鋪設；與共用布局核對 | 高速低格在高側鄰軌存在時形成斜坡，沒有一格垂直牆被當成可通行平軌；本例驗幾何修正，不保證所有反轉解除 |
| R1-003 | 共用布局第一格升坡使用原版 powered_rail 並給電；低側高速平軌，四方向×配置三點，SP／DS；再從高側下坡 | 有效同 Y 坡底／坡頂連接，供電進入时保持預定行進方向、不突然反轉；若重現，I-026-02 未解決 |
| R1-004 | 第一格升坡改原版 rail；其餘供電高速路段給足進入動量；四方向×三點，SP／DS，上坡／下坡 | 有效接口不意外反轉，正常無動能回滾須分開記；不要稱一般 rail 本身可供電 |
| R1-005 | 第一格升坡改 high_speed_rail，整條供電；四方向×三點，SP／DS，上坡／下坡 | 高速自身斜坡與平軌、坡頂正常銜接；不靠強制方向補丁掩蓋碰撞；通過亦需使用者確認 |
| R1-006 | 複製同一布局／空礦車起始方式，用原版 powered_rail 取代高速路段；與 R1-003／004 對照 | 记录實際原版結果以排除布局／供電／起步條件；不因控制對照失敗而宣稱高速通過 |

來源：使用者高速例外決策；原版 powered_rail 的六 shape／旋轉／模型；固定版 RailState 成坡與連接、AbstractMinecart 移動／動力分支及 Entity 碰撞來源。全部僅作事先預期，實際結果由使用者確認。其他特殊軌道的禁坡以程式／來源核對保持，未實作者不安排虛構遊戲測試。
