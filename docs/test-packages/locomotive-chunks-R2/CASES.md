# 新 D3 人工案例（全部待使用者）

共用：新世界／備份後的 NEW 測試副本，遠離出生點；只用 Minecraft、NeoForge、Simple Rail，無 `/forceload add`。從 R1 升級先完成 01。一般流程可沿用 R1 的持續供電測線，但**票證預期改用本頁**：使用者在 `(1024,64,1024)` 附近鋪長程持續供電軌道、放車頭並以動力／推動發車，標記 `/tag @e[type=simplerail:locomotive_cart,sort=nearest,limit=1] add LC_R2`。所有玩家離開 view-distance／simulation-distance 範圍，例如 `/tp @s 0 80 -1024`。console 以 `execute in minecraft:overworld as @e[type=simplerail:locomotive_cart,tag=LC_R2] run data get entity @s Pos` 查行車；console 命令不加 `/`，不要傳送到車頭旁遮蔽問題。

| ID | 操作 | 事前預期 |
| --- | --- | --- |
| LC-R2-01 R1 升級清理 | 備份 R1 有長途歷史票證的 NEW 世界；正常關服後換 R2 啟動，先不靠近舊車。再靠近既有**整列**使車頭和車廂載入，發車。選用 NBT 觀察見 README。 | 本 controller 的 R1 歷史票證被清理，沒有舊索引時不猜 owner 位置；不刪車、不影響原版／其他 controller 票證。載入整列後產生新索引，恢復行車。 |
| LC-R2-02 無玩家長途 | 單車與既有可用長編組各跑一段跨多個 chunk 的持續供電路線；玩家遠離，console 每 10 秒查位置，至少觀察 60 秒，避免到終點。比較短途與再前進 100 個 chunk 後的相同編組票證集合。 | 位置持續變化；票證跟目前位置／目標移動，舊路線不累積。相同編組的集合會隨邊界形狀稍變，但不與總里程成正比。 |
| LC-R2-03 尾車覆蓋 | 使用可連結的長編組，讓頭尾跨數個 chunk，尾車超出車頭周圍一圈，亦測蛇形彎道；全員離開。 | 尾车自身位置／目標仍在必要集合內；無卡尾、遺失或無預期斷鏈。車距仍為 1.35×序號。若現有編組數無法達到此距離，該子例記條件不足，不猜測通過。 |
| LC-R2-04 高速／斜坡／路口 | 在已授權高速斜坡、一般鐵軌、高速鐵軌與十字／T 型路口跨 chunk；配置最高支援速度，正負 X/Z 邊界雙向跑單車／編組。 | 新 chunk 未就緒時整列等待；就緒後依原速度機制與既有方向規則恢復。無永停、坡底反轉、車距大幅跳動；不因回收把尾車卸載。 |
| LC-R2-05 停車／計時／再發車 | 車頭／編組在計時停車轨等待，玩家離開；再正常放行。 | 停車保留必要集合，計時與再次發車可運作。這不是實際卸載案例，不用它簽 D5 卸載暫停通過。 |
| LC-R2-06 刪車／解除連結 | 先記一列 owner，再普通永久移除車頭及用 destory_rail 移除；另測中間車破壞後尾段脫離。 | 車頭永久移除後其票證／索引歸零，不等重啟；編組切斷後脫離部分不再由原 owner 保留。未改原車廂刪除／掉落行為。 |
| LC-R2-07 多列共享 | 兩列在相同 chunk 但互不碰撞的軌道停車／行駛，刪除其中一列；再讓剩餘列離開此區。 | 刪除一列只回收該 owner 的票證，另一列照常運作；最後無列車需要的舊區塊不殘留本 controller 票證。 |
| LC-R2-08 關閉／重新啟用設定 | 已載入與遠端已登錄列車並存；把 COMMON 歷史鍵改 false 並確認 reload 生效。查票證，再改 true。若環境不能 live reload，分別用停服修改後重啟，標清測的是哪條路徑。 | false 下一 server level tick 清全部本模組 runtime 票證／索引，包含未實例化 owner；true 為已載入列車重建。已因停用而卸載的車需載入一次，不能把它當重啟恢復故障。 |
| LC-R2-09 全員離線／重啟 | 讓新索引列車遠離玩家，玩家全部到另一維度，再全部離線但 dedicated server 運作超過 60 秒；正常 save-all flush／stop／重啟後不靠近鐵路。 | 無玩家仍移動；正常重啟從新索引恢復，不需玩家追車；不恢復全歷史路線。離線但 server 運作與停止 server 的時間分開。 |
| LC-R2-10 維度／世界隔離 | 兩維度同座標放不同車、各跑一段；若可行測車頭換維度。單人世界 A 放車後退出，進 B 同座標放另一車。 | owner 依維度隔離；換維度不留舊維度該車票證，目標維度按自己的編組可用情況登錄。A queue／leases 不污染 B，正常關服不誤判永久刪車。跨維度編組本身不新增保證。 |
| LC-R2-11 缺車／延遲 IO／恢復 | 在獨立副本使用較慢儲存或已知未載入尾車場景；觀察 waiting 警告，再把缺車實際位置載入。不要刪原存檔或以移除車頭冒充未載入。 | UUID 不被當成已刪；整列等待時已載入車廂不被動力軌拖走；IO 完成且車輛可用後自動恢復。無法製造延遲條件則標條件不足。 |
| LC-R2-12 中斷保存／索引失配 | **只在可丟棄副本**測非正常中斷；或使用先前备份與索引失配副本。重啟先等待 IO，查看 log，再靠近真實列車位置。 | 索引內 IO 未完成不誤清；全部索引 chunk 已 ready 卻找不到 owner 時，釋放其票證、保留暫停索引並警告，不刪實體、不全圖搜尋。手動載入真實位置重新登錄。索引／entity 檔非交易保存，不承諾任何損壞都自動恢復。 |

人工通過需由使用者確認；效能量化門檻仍待事先定義，本包不捏造 TPS、記憶體或延遲結果。若失敗，回報 ID／現象即可；補充 UUID、位置、設定、log、NBT 比較可協助定位但非結案必要附件。
