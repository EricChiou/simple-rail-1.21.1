# T-120 診斷案例（實際結果均待使用者）

下表的「預期」是 [OLD 來源模型與 NEW API 對照](../../evidence/T-043/INVESTIGATION.md)給這支**診斷 JAR** 的事先判準，不能視為 OLD 或正式產品已驗證。初始測試可用 `INSTALL.md` 的 `(100,64,100)`。每個案例可換新的測試區，避免前次礦車占位干擾。若沒觀察到 `[T043] START`，先查安裝／供電／OP，不把該案例記成「未重現」。

| 案例 | 操作 | 診斷預期 | 實際結果／可選證據 |
| --- | --- | --- | --- |
| `T120-01` 持續供電 | 上方單箱槽 0 放普通礦車；清空預期生成格，從無電改為相鄰紅石方塊持續供電，記第一個 `[T043] START`。保持供電，待生成車離開或清走後，於另一空側放／移普通方塊。 | 若真的再次收到 powered `neighborChanged`，出現新的 `run`，有空位時再嘗試生成；模型沒有 TRIGGERED 邊緣閘。若仍有車占位，見 `BLOCKED` 而非「沒有回呼」。 | 待使用者填／確認；可選兩次 run、供電與占位時序 |
| `T120-02` 斷電再供電／重複更新 | 重複 01，分別做「有電但不斷電的 2 次鄰居更新」與「斷電→再上電」。每次先記槽位與目標位置是否有車。 | 每個有效且 powered 的鄰居回呼均可進掃描；無電更新不掃描。掃描次數不等於成功生成車數。 | 待使用者填／確認；可選 run ID 與紅石切換順序 |
| `T120-03` 空格／間隔 | 箱槽 0 放普通礦車、槽 1 留空、槽 2 放箱子礦車，其餘留空；用 `/t043 scan 100 64 100`。 | 槽 1 記 `SKIP`，槽 2 仍走訪並按 CHEST 嘗試生成；樣板不被扣除。 | 待使用者填／確認；可選 `SLOT 0..2` 與箱子前後 |
| `T120-04` 阻擋礦車 | 準備槽 0 與後續有車的樣板，分別在槽 0、槽 2、以及**樣板空槽 1** 的公式位置預放一輛礦車；每次另起乾淨區／清車，手動 scan。 | 命中的槽記 `BLOCKED` 並終止本輪；後續槽不再走訪，即使阻擋槽的樣板是空的。首次槽阻擋應無新車。 | 待使用者填／確認；可選阻擋位置、`stopped_at`、車 UUID |
| `T120-05` 四朝向位置 | 以 `/setblock` 將同一診斷方塊改 `facing=east/west/north/south`；箱槽 0、2 各放普通車，逐方向於乾淨區 scan。 | E 槽 i `(x+1.5,y,z+i+0.5)`；W `(x−0.5,y,z−i+0.5)`；N `(x+i+0.5,y,z−0.5)`；S `(x−i+0.5,y,z+1.5)`。`SLOT place` 應符合公式；實際車落地與移動另外記。 | 待使用者填／確認；可選方向、槽→UUID→座標 |
| `T120-06` 原版車種／名稱 | 依序於單箱槽 0 放普通、箱子、熔爐、漏斗、TNT 礦車物品；有權限時可另試命令方塊礦車。再將箱子礦車**物品堆**改自訂名稱後重試，每種另用空位 scan。 | 診斷 `kind` 依 Item 身分為 RIDEABLE／CHEST／FURNACE／HOPPER／TNT；改物品自訂名不改類別；其他 MinecartItem（如 command block）按 OLD switch 預設分支標 RIDEABLE。這只驗 NEW 診斷映射，不證 OLD `toString` runtime。 | 待使用者填／確認；可選 item ID、顯示名、kind、實際車種 |
| `T120-07` 第 0 格車頭 | 使用 `simplerail:locomotive_cart` 物品分別放槽 0、槽 1，其他槽放普通礦車，並測兩個車頭及中途空格／阻擋。每組於乾淨區 scan。 | 任意槽的車頭 token 以**原版爐車替身**生成；只有槽 0 token 使 `head_at_zero` 有值，`link_plan` 列本輪普通車 UUID。沒有真正連結、車頭型別或同步驗證。 | 待使用者填／確認；可選槽位→UUID 與 `link_plan`，真編組另待 T-059／T-060 |
| `T120-08` 27 格不消耗 | 上方箱槽 0–26 可放混合樣板（含空格、不同堆疊數／自訂名）；先記各槽，再於乾淨位置 scan，最後重開同一箱子比較。 | 診斷 JAR 不呼叫移除或 `shrink`，同一箱 27 格內容保持；玩家主動移動物品另算。正式專用 BE、GUI、保存與同步不由本包驗收。 | 待使用者填／確認；可選 27 槽前後快照與 log |

如使用者判定某項現象是問題，請標示案例 ID、你期望的觸發／位置／車種及實際差異。T-045／T-046 只對已確認問題訂修正，不因診斷模型本身就加入節流、消耗物品或外部車種。T-120 是使用者任務；其餘正式驗收仍由 T-047、T-060、T-082 等承接。
