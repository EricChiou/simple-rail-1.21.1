# T-121 操作案例與預期（均未執行）

共同準備：另建測試世界，使用本包固定 JAR；開作弊／OP，記錄每個 head／cart 的 UUID（`/t054 link` 和 `/t054 inspect` 在 server log 中列出）。除非案例另說明，先在連續軌道上用診斷指令連結。下表中的「可見」指 `inspect` 的 ordered UUID 及 `loaded`，不要求未載入車廂繼續即時移動。世界操作與觀察只由使用者執行。

| 案例 | 操作步驟 | 預期與待回報實際結果 |
| --- | --- | --- |
| T121-01 空列車 | 放一個車頭，不連車廂；`inspect`，移動一段、存檔重啟再 `inspect`。 | `order=[]`，無異常或新增車廂；回報重啟前後清單／現象。 |
| T121-02 多節次序／重複 | 放車頭和兩節普通礦車；依序 `link` A、B，再嘗試重複 `link` A；`inspect`，移動與停止。 | 第三次 `linked=false`；清單始終 `[A,B]`，兩車依序跟隨；回報 UUID、順序、跟車／停止現象。 |
| T121-03 跨區塊 | 將車頭與車廂分置區塊邊界兩側，連結後使車頭跨邊界，使用 `/t054 inspect`。 | UUID 次序不因跨界被縮短；已載入車廂仍可跟隨。回報區塊座標、載入先後與清單。 |
| T121-04 車廂晚載入 | 將車頭／車廂跨數個區塊連結；以 `/forceload add` 保持車頭區塊，讓車廂區塊卸載，`inspect`；再使車廂區塊載入，`inspect`。 | 車廂暫時 `loaded=false` 時仍保留 UUID／owner；重載後同 UUID 恢復 `loaded=true` 且次序不變。回報時間順序及位置；若實際無法分別卸載，標「證據不足」而非通過。 |
| T121-05 讀回與暫時 null | 沿用 T121-04 的跨區塊編組；車廂卸載時存檔／關服，重啟先載入車頭，再載入車廂，兩次 `inspect`。 | `Train` 順序、stop 位置／跟車狀態不因首次 null 直接丟棄；讀回後同 UUID。回報重啟先後、前後清單與位置；若頭／車同時載入，標記時序不足。 |
| T121-06 跨維度同時運作 | 在主世界、地獄各建一頭兩車（或一車），各自 `link`／`inspect`，交替進維度並使另一側持續載入。 | 每維度只見本維度 head 與 UUID／owner；互不阻擋或污染。回報兩組 UUID、維度、清單與實際現象。 |
| T121-07 同程序切換世界 | 單人 client 保持程序啟動，從測試世界 A 退到標題，建立世界 B 並放置／連結新編組，回 A `inspect`；若使用 dedicated server，需可在同 JVM 中切換存檔的受控環境，否則此例列「待確認」。 | A、B 清單各自獨立；沒有 A 的 UUID 出現在 B。回報世界切換順序；若沒有同程序條件，標「證據不足」。 |
| T121-08 永久移除與未載入車廂 | 車頭／車廂跨區塊連結並確認 UUID；保持車頭載入、讓車廂區塊卸載；永久移除車頭（非單純卸載），再重載車廂，建立新車頭並嘗試 `link` 它。 | 新車頭可連結該車廂；舊 owner claim 已解除。另可在正常載入時移除單一車廂，觀察正式 unlink UI 尚未完成的限制；回報兩組頭 UUID、連結成功與否。 |

每例實際結果在 `results.json` 留空等待使用者。分類為「已確認問題／未重現／證據不足」，並註明是否測到卸載與重載這個必要條件。`/t054` 是診斷指令，測完後正式產品不含此指令；不要把它當成 T-057／T-059 的扳手或發射器驗收。OLD 對照皆為**依原始碼推定／待確認**，未執行 OLD build／遊戲。
