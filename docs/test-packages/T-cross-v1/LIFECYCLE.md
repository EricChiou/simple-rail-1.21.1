# T-123 兩種路口暫存觀察案例（待使用者執行）

共同布置：每一案例用新建、互不干擾的平坦軌道，建議路口中心 `(100,64,100)`，四側接原版平面鐵軌。測試普通礦車，避免車頭的 D3 區塊載入影響卸載案例。T 路口以 `/setblock 100 64 100 simplerail:t_cross_rail[direction=north]` 建立，再用紅石供電／斷電；實際 `powered` 以 F3 指向方塊顯示的狀態或 `/execute if block` 條件查詢核對，不以命令輸入值代替實測。每次記路口位置、維度、車 UUID、輸入方向／速度、紅石狀態、`/data get block 100 64 100 PendingPassages` 與車的實際去向。路口方塊實體的 PendingPassages 是 NEW 暫存欄位，並非 OLD NBT。

測試中途狀態時，用 OP 或 server console 執行 `/tick freeze`，玩家不要乘坐受測礦車；以 `/tick step 1t` 逐 tick 放行，直到 `/data get block 100 64 100 PendingPassages` 顯示該車 UUID，再檢查／存檔。若命令在受測伺服器不可用或未能截住第一次過車，該子案例標「條件不足」，不虛構結果。結束後執行 `/tick unfreeze`。以 server console 執行時省略前導 `/`。存檔／關服僅作用於獨立測試世界。

每行的 C／T 分別表示十字、T 型；對每個類型各記一個獨立案例，例如 `T123-01-C`、`T123-01-T`。T 型至少選一組 `direction` 與 `powered`，在案例表註明實值；T-069／T-071 才完整遍歷 32 組行車矩陣。

| 組別／案例 ID 後綴 | 操作步驟 | 預期與需記錄的實際結果 |
| --- | --- | --- |
| 01-C／T 不同維度同座標 | 在主世界及地獄的相同 `(x,y,z)` 各建立同類路口。主世界一台車停在第一次過車暫存階段；地獄另一台車獨立過車，再返回主世界。 | 兩處 `PendingPassages` 的 UUID／速度／出口各屬各世界；地獄操作不覆寫主世界，恢復後車各走自己的出口。記雙維度座標、UUID、暫存與出口。 |
| 02-C／T 同程序切換世界 | 單人 client 在世界 A 留下一筆中途暫存、退回標題而不結束程序；建立世界 B 的相同路口座標，過車並查暫存；再回 A。 | B 不見 A 的車 UUID，A 的保存值按自身存檔恢復。如果環境不能在同一 JVM 切換兩世界，此例標「條件不足」，不以重開程序替代。 |
| 03-C／T 破壞／重放 | 將一車停在第一段暫存後查 `PendingPassages`；記 UUID，清走車，破壞路口並在原座標重放同種方塊；再查新 BE 並以另一車過車。 | 新方塊沒有舊 UUID 暫存，不會把新車送到舊目的格；不影響另一世界同座標的路口。記前後 BE 值及新車去向。 |
| 04-C／T 卸載／晚載入 | 一車停在第一段暫存，記 UUID；玩家離開足夠距離使路口 chunk 卸載，之後返回讓它重載；必要時比較 `/forceload query`，不要新增票證政策。 | 待處理 UUID／速度／目的格在保存與重載後仍可用；車續行一次，沒有不同世界殘留。若區塊從未卸載，標條件不足。 |
| 05-C／T 中途存檔重啟 | 同第一段暫存，在 freeze 狀態執行 `/save-all flush` 並正常關服；用同一 JAR 重啟後查方塊／車，再解除 freeze 或步進直到車通過。 | 車依保存的出口和速度完成第二段，不永久卡在路口、不生成額外車；記重啟前後 UUID、暫存與位置。若重啟時已立即完成，記可觀測狀態，不倒填未看見的中間值。 |
| 06-C／T 兩車同時通行 | 從相對兩側各放一台普通礦車，以動力軌或 `/tick step` 盡量使兩車在同一 tick 進路口；查暫存中的兩 UUID 與各自出口，再放行。 | 兩車互不覆寫彼此的暫存，各按進入時方向／紅石路徑前進；如果碰撞使兩車未同時到達，記實際順序並標「同時條件不足」。 |

每類路口的預期出口依 [NEW T 型出口表](CASES.md)（十字仍直行）比對；舊遊戲行為仍為「依原始碼推定／待確認」。只將實際出現且有操作條件的現象列為確認問題。各實際結果在 `results.json` 保持空白，待使用者直接確認或回報；log、截圖、世界副本可選附。
